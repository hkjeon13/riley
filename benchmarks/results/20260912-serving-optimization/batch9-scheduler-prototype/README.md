# Batch9 scheduler policy prototype

The scheduler policy is implemented and CPU-tested only in `/tmp/riley-batch9-local-scheduler-20260912`. The main repository's 341 original source files remain byte-identical to `source-before.json`. The source copies here and `scheduler-policy.patch` are review artifacts, not an applied production change or optimization acceptance.

Use `Scheduler::new_with_execution_shape(config, layout, ExecutionShapePolicy::CompletePrefill128DecodeN)` for the proposed owner. `Scheduler::new` and public `SchedulerConfig` literals retain the General policy. The new constructor requires capacity 2 or 4, budget/chunk 128, sequence 160, SmolLM2 KV geometry 30 layers/3 KV heads/head dimension 64, and at least ten promised/physical blocks per active request. Admission accepts only P128, O1–32 and input IDs below 49152, reserving the fixed 160-position envelope even for O1. Returned IDs are checked against that vocabulary before any result commit/publication.

The policy selects one whole prefill or all ready decode requests, never mixed. When both classes are ready, a prefill is followed by decode before another prefill; ready-time/request-ID ordering within each class is preserved. Partial decode buckets dispatch immediately. The previous dispatched class is recorded at validated settlement: no other plan can be prepared while one is in flight. NotDispatched rollback and rejected plans/results do not count as progress. Explicit DeviceQuiescedMutationUnknown settlement conservatively counts the possibly dispatched class while preserving existing poison/reclamation behavior. Unknown GPU completion must still retain the outstanding iteration until quiescence is established.

The recorded Rust 1.85.0 command in `test-run.json` passed 57 CPU tests: 12 new policy tests, 31 existing library tests and 14 legacy simulations. Coverage includes the unchanged General 127-token mixed plan, strict shape/config/request rejection before promises, fixed promises through queued admission, continuous short-prefill pressure, NotDispatched retry, invalid output tokens, cancellation with 4→3→1→2 active-row transitions, O32 termination, and failed-dispatch survivor progress. No CUDA features were enabled. `rustfmt --check` passed, and the patch was checked against the exact stored before source. Independent read-only review found no concrete blocker; it did not rerun tests.

`receipt.json` binds the patch, before/after maps, all four changed/new source copies, compiler, test/format logs and review record. Existing source changes are limited to scheduler config/lib/scheduler, with one new integration-test file. The initial source was a copied working-tree snapshot, not a new Git commit; inherited dirty work remains part of that exact base.

This is one preparatory component of the linked multi-sequence batch. Native arithmetic admission, descriptor/graph-owner implementation, runtime/server integration, full GPU correctness, and matched serving measurement remain separate unfinished work. These CPU results make no numerical, latency, throughput, or high-concurrency claim.
