# A100 모델별 성능 수치 (Riley vs vLLM 0.27.1)

2026-10-29 정리, 2026-10-31 갱신(Qwen3-14B 재측정, DeepSeek-R1-Distill-Llama-8B 추가). A100-SXM4-40GB 한 장, 8셀(C1/C8/C16/C32 × fixed/natural), warm-up 32 + 측정 192, Riley와 vLLM을 같은 실행에서 순서를 바꿔 2회 측정한 평균이다. 모델마다 가장 최근의 8셀 판정 측정을 썼다. 원본은 호스트 `aws-a100`의 `/mnt/efs/nlp/psyche/riley-261013/evidence/<run>/result.json`이다. 판정 기준과 종료 근거는 [model coverage](model-coverage-a100.md)에 있다.

각 칸은 **Riley / vLLM** 값이다. 굵게 표시한 칸은 Riley가 기준에 못 미친 곳이다(C8–C32의 처리량·TPOT은 vLLM보다 나쁨, C1의 처리량·TPOT은 ±3% 밖, TTFT p50은 vLLM보다 큼). E2E는 판정 기준이 아니라 표시하지 않는다.

fixed는 출력 길이를 고정한 워크로드, natural은 EOS까지 생성하는 워크로드다. C 뒤의 숫자는 동시 요청 수다.

- Qwen2.5-0.5B와 SmolLM2-360M은 native 프로필의 8셀 측정이 없다. 8셀 표는 10-14의 구 설정 값이고, native 프로필 결과(c1·c32 4셀)는 맨 아래 표에 따로 둔다. SmolLM2-360M c32-fixed TPOT의 미달(4.08 / 3.94)은 구 설정 값이며, native에서는 3.27 / 3.95다.
- Qwen2.5-14B는 vLLM이 기본 메모리 설정(0.6)으로 로드되지 않아 vLLM만 `--gpu-memory-utilization 0.9`로 바꾼 별도 조건이다.
- Qwen2.5-Coder-7B의 natural 셀 E2E가 Riley 쪽이 긴 것은 출력 길이 차이 때문이다. Riley가 EOS까지 더 긴 출력을 낸다. 같은 셀의 TPOT·처리량은 Riley가 낫다.
- 2026-10-29 추가 측정(같은 아키텍처 모델 7개): Qwen2.5-Coder-1.5B/3B/14B, DeepSeek-R1-Distill-Qwen-1.5B/7B/14B, Qwen3-14B. 14B 셋은 vLLM 메모리 0.9 조건이다. Coder는 `b74361d3`, 나머지는 `d431ddff` 바이너리로 쟀다. 둘 다 `d41d7dfc0` 코드에 설정 파싱 수정만 더한 것으로, 커널·수치 변경은 없다.
- DeepSeek-R1-Distill-Qwen은 `config.json`의 `use_mrope: false`, `tokenizer_config.json`에 `added_tokens_decoder`가 없는 점, 토크나이저 `model_max_length`(16384)가 모델 컨텍스트(131072)보다 작은 점 때문에 로드되지 않았다. 셋 다 로더에서 받아들이도록 고쳤다. 추가 토큰은 `tokenizer.json`을 기준으로 삼고, 길이 상한은 HF·vLLM처럼 참고값으로 본다.
- Qwen3-14B는 10-29 측정(`qual-nv-qwen3-14b-attempt02`)에서 8셀 중 7셀이 미달이었다(C1 TPOT 26.7 / 22.3 ms). 원인은 A100 cuBLASLt 등가 표에 Qwen3-14B의 gate|up(5120→34816), down(17408→5120), LM head(5120→151936) 항목이 없어 128행 anchor 구성으로 돌던 것이다(M=1 gate|up 334.6 µs vs 등가 구성 255.8 µs). `gemm-equiv-a100-attempt03`으로 찾은 비트 동일 구성을 표에 넣고 다시 쟀다(`attempt04`, 바이너리 `riley-fix-535f043c`, GPU 7 단독). 8셀 모두 충족이다(C1 TPOT 22.5 / 22.3 ms).
- DeepSeek-R1-Distill-Llama-8B는 10-29에는 로드되지 않았다. `tokenizer.json`에 BOS를 붙이는 post-processor가 없고 BOS는 `tokenizer_config.json`의 `add_bos_token`으로만 정해지는데, Riley가 이 형태의 Llama 3 토크나이저를 거부했다. 로더가 템플릿 없는 토크나이저에서 `add_bos_token`·`bos_token`을 읽어 BOS를 붙이도록 고쳤다(DeepSeek-R1-Distill-Qwen에도 같은 규칙이 적용되어 BOS가 붙는다. transformers 5.19와 그 토크나이저를 쓰는 vLLM 0.27.1은 이 BOS를 빠뜨린다 — [6절](model-coverage-a100.md#6-품질과-큰-모델-2026-10-31)). 같은 바이너리로 8셀 모두 충족이다(`attempt03`, GPU 7 단독).
- 10-29의 HF BF16 일치 수(eager 기준, 15개 프롬프트)는 기준 자체가 잘못되어 철회한다. transformers 5.19의 BF16 `eager` 어텐션은 `sdpa`·FP32와 다른 토큰을 내고, 10-29 vLLM 측정은 `generation_config.json`의 repetition penalty가 켜진 상태였다(Qwen2.5 계열). 고친 품질 비교는 [model coverage 6절](model-coverage-a100.md#6-품질과-큰-모델-2026-10-31)에 있다. 일곱 모델 모두 Riley 출력이 C1·C8·C32에서 15개 프롬프트 모두 같았다는 동시성 불변 결과는 그대로다.
