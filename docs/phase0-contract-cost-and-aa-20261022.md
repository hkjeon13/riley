## 1. A/A: 같은 v15C 바이너리끼리 비교

v15C(sha `233c3a6a…`)를 before/after 양쪽에 같은 argv로 넣고, C16·C32에서 각각
새 프로세스 10쌍(64 warm + 192 측정)을 돌렸다. strict 출력은 모든 arm에서 eager 참조와 일치했다.

| | C16 | C32 |
|---|---:|---:|
| 10쌍 중 ">2% tail 악화" 경고가 붙은 쌍 | 4 | 5 |
| v15C~v19B 규칙(5쌍 중 하나라도 경고면 탈락)의 오탐 확률 | 97.6% | 99.6% |
| 5쌍 캠페인당 평균 경고 수 | 2.5 | 3.5 |
| "5쌍 처리량 모두 양수"를 만족할 확률 | 2.4% | 0% |
| 5쌍 중앙값 처리량 변화의 95% 범위 | −0.20 ~ +0.45% | −0.89 ~ +0.65% |

두 C 중 하나라도 경고가 붙을 확률은 99.99%다(252×252 부분집합 조합).
arm 간 변동계수는 처리량 0.6–1.2%, TTFT/TPOT p95/p99 1.1–2.3%, 토큰 ITL p99 0.9–3.0%다.

**결론:** 기존 규칙은 노이즈를 걸러내지 못한다. 동일 코드도 사실상 항상 탈락한다. 반면 중앙값 처리량의 노이즈는 ±1% 이내다.
이 결과는 이후 후보에만 적용하며, v16~v19의 판정을 다시 내리지 않는다.

**제안 게이트(이후 후보용):**
- 처리량: 5쌍 중앙값 변화가 A/A 95% 상한의 2배(C16 +0.9%, C32 +1.3%)를 넘을 것
- tail: 각 지표의 5쌍 중앙값 악화가 A/A 95% 상한 + 1%p 이하이고, 같은 방향으로 악화한 쌍이 4개 이하일 것

## 2. 수치 계약 비용: strict vs native vs vLLM

- **strict**: 채택된 v15C(owned-hf-eager-bf16-v1, budget 576)
- **native**: 같은 v15C 바이너리에 10/14 A100 스크리닝 플래그 세트(배치 불변, budget 256, 이 워크로드용으로 재튜닝하지 않음)

## 3. 해석

1. **격차는 거의 전부 수치 계약에서 나온다.** 같은 바이너리가 native 프로파일로는 fixed 전 셀에서 vLLM과 동률 이상(0.998–1.066배)이다. strict는 0.58–0.77배이고, 긴 출력의 natural C32에서는 0.29배다.
2. **native 트랙의 남은 약점은 두 가지다.**
   - natural C32 처리량 0.914배, TPOT p50 +11%: 긴 문맥 decode attention
   - 버스트 TTFT p95/p99: fixed C32에서 vLLM보다 1.4–1.6배

   10/14 스크리닝과 같은 결론이다.
3. **native의 HF 일치는 vLLM과 비슷하다.** fixed는 vLLM보다 조금 낮고, natural은 더 높다. 결정성은 native가 vLLM보다 강하다.
